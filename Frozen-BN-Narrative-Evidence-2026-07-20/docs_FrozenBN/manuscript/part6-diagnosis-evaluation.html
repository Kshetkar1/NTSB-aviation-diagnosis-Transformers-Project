Part 6 — Evaluating Diagnosis: Cause Categories Across a Taxonomy Break

6.1 The problem nobody warned us about: NTSB changed its language in 2008

Vocabulary — the two coding eras. Through 2007, NTSB coded causes with a legacy system: a "subject" (e.g. directional control, weather condition) optionally attached to a person (Pilot-in-command, Company/operator management). From 2008, it switched to CICTT (the CAST/ICAO Common Taxonomy Team system): hierarchical codes like Personnel issues → Task performance → Use of equip/info → Aircraft control → Copilot. The two vocabularies do not map code-to-code. Our network is built on legacy-era data and our test years are CICTT-era — so naive cause matching across the split is impossible by design of the data itself.
Why we solved it with a rollup instead of giving up. CICTT's own top level already defines four broad categories — Personnel, Aircraft, Environment, Organizational — and every CICTT code names its category in its prefix. So the fair comparison level is the level the modern taxonomy itself declares: roll both eras up to the four categories. CICTT-era findings map trivially (read the prefix); legacy findings map through explicit keyword rules (categorize_legacy in tests/diagnosis_heldout_eval.py) covering 97.6% of the window's cause/factor findings. We call this the era-fair evaluation.

6.2 The rollup is a rule set, and its influence is bounded

Hand-written mapping rules are a place bias can hide, so the honest question is not "were the rules blessed by a reviewer?" but "how much could the rules be wrong by, and would that change any conclusion?" We answer the second question, because it is the one we can actually answer.

A stratified 75-row sample of the rule set's decisions (50 legacy subject+person rows weighted by frequency, 25 CICTT rows as the anchor — their prefix IS the category, so they define the reference standard) was reviewed for internal consistency against CICTT's own conventions.

What this review is not. The review pass was an AI assistant and the rows were then checked by the first author. That is self-review with extra steps, not independent dual coding, and we make no inter-rater claim from it. It found and fixed two real rule defects, which is worth something; it is not validation. The evidence that carries the paper's robustness claim is the bound in the next paragraph.
The sensitivity bound — the actual evidence. All seven contested rows together (2 corrected + 5 boundary) touch 316 of 5,062 window cause findings, 6.2% of the mapped mass. Reassigning a category perturbs the retrieval neighborhood and the network's node scores in the same direction for every predictor, so the worst case a full reassignment of that mass could produce is ≤ 2 percentage points on absolute accuracy, identically signed across predictors. Every gap the paper claims is far larger than that — retrieval over the BN event path is 26.5 points, the BN event path over the frequency baseline is 11.9 — so no admissible re-reading of the contested rows can reorder them. The measured effect of the two corrections confirms the scale: retrieval moved 83.8% → 84.2% and nothing else moved at all. Absolute accuracies therefore carry a residual mapping uncertainty of ≤ 2 points, and that is how they are stated.

6.3 The task and the metric, stated precisely

Remember from Part 4 that diagnosis is not a second system: the BN predictors below take the same parsed narrative evidence as the severity pipeline and read the upstream side of the same joint posterior — tests/diagnosis_heldout_eval.py queries P(node = Yes | evidence) for every candidate cause, finding, and person node in the network (evidence nodes excluded, so the parser cannot grade its own input), then ranks the four categories by their best node. What changes between Part 5 and Part 6 is only which nodes get scored.

Vocabulary — truth sets and set-membership top-1. An accident usually has several coded findings, so its truth is a set of categories (e.g. {Personnel, Environment}). Our headline metric: the prediction is correct if the model's top-ranked category is in the truth set — the decision-relevant question "is the top suggestion a coded cause?" This is a lenient criterion, so we also publish the strict view (exact per-category recall) alongside it, plus MRR (mean reciprocal rank: 1/rank of the first correct answer, averaged — 1.0 means the top answer is always right). Definitions are printed inside the results file itself, outputs/diagnosis_heldout_eval.md, so no reader has to guess.

Cohort: the 253 of the 296 held-out accidents that carry cause findings (outputs/cohort_manifest.json proves it is a subset).

Recall balance: retrieval is even across the three common categories (Personnel 68% / Aircraft 62% / Environment 72%) — it is not just parroting "Personnel." The rare Organizational class is effectively unrecovered: retrieval, the frequency baseline, and the lift ranking never rank it first (0 of 25) and the BN event path does so exactly once (1 of 25) — the same class-rarity failure mode as fatal injuries in Part 5, and disclosed the same way.

How to read this table. Three findings, in the order of their strength. (1) The headline readout is retrieval at 84.2% — narratives carry strong diagnostic signal, nearly doubling the frequency baseline with zero training. (2) A supervised model beats it by 3.9 points (88.1%, p = 0.041) — the measured price of needing no labels, disclosed, not hidden. (3) The network's event-evidence path at 57.7% is a structured-inference result and a partial negative result at the same time, and it is not a headline. Positive: parsed narrative facts propagate through Zhang's CPTs to cause nodes the pipeline was never pointed at and land significantly above baseline (Holm p = 0.0007) — evidence that event evidence reaches upstream cause nodes at category granularity. Negative: it loses to plain retrieval by 26.5 points, so as a predictor of cause category it is not competitive; the fire-node experiment (Part 7.6) further shows BN cross-node inference does not beat retrieval on held-out fire (ROC AUC ~0.38–0.46 vs retrieval ~0.96–0.98), so we do not present cross-node inference as predictive lift.
What we tried that did not work (and kept in the paper). Ranking cause categories by lift (posterior ÷ prior, "which category increased most") sounded cleverer than ranking by posterior. It scores 50.2% — barely above the baseline — because lift amplifies noise on small priors. We report it because negative ablations are how a reader learns the design was chosen by measurement, not taste (the same lesson as bn-fused in Part 4).

6.5 What this evaluation does — and does not — cover

The honest scope statement. The pipeline computes posteriors for every individual upstream node (hundreds of specific findings, occurrences, and persons — the demo shows them for any narrative), but what is quantitatively scored here is only the four-category rollup. Finding-level or occurrence-level diagnosis accuracy is not evaluated — partly forced by the data (the 2008 taxonomy break means held-out truth labels do not share a vocabulary with the network's legacy-era nodes below the category level). The fire-node cross-inference experiment (Part 7.6, outputs/fire_node_cross_inference.md) is now done and negative: BN ROC AUC ~0.38–0.46 on coded fire (below chance) vs retrieval ~0.96–0.98 on identical text. Do not claim held-out predictive lift from BN cross-node inference; the precise claims are: (1) narratives drive diagnosis at the category level (this part), and (2) the BN provides auditable joint reasoning and what-if semantics — not outperformance over neighbour voting on unobserved nodes like fire.
