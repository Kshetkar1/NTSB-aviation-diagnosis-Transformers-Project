Part 1 — What & why

Black The problem · p.__ §1

  • NTSB report = coded events + written factual story
  • Codes lose wording, timing, crew context
  • Blue Zhang (2021): Bayesian network from codes only, 1982–2006
  • Our question: Can a new story (after stripping cheat phrases) update that same network and predict NTSB injury, damage, cause type?

Black Five goals

  1. Rebuild Zhang’s network from 1982–2006 codes
  2. Match published checks (Table 7, fire rate, Table 9/10)
  3. Turn stories into node updates on network locked after build
  4. Score 296 accidents (2007–2019) — NTSB codes for grading only
  5. Side: GPT reads text → node labels only (network does all probabilities)

Green Research questions

Main: After Step 1 (strip cheat phrases), can story → network match NTSB codes on 2007–2019?

Side: Can GPT label nodes without outputting probabilities?

NOT: “ChatGPT predicts the accident.”

Why we designed it this way

  • Extend Zhang: person nodes + 4-level injury/damage (see table above)
  • Strip cheat phrases: “substantial damage” in text = reading the answer
  • 296 = exam: only comparison classifiers train on 1982–2006 labels
  • 4 cause categories only: NTSB changed coding in 2008 — we score Personnel / Aircraft / Environment / Organization, not exact phrases like “compressor blade”
  • Severity through network = neighbor vote on top pick: same #1 answer 296/296 — network enables Table 10 what-if, does not beat neighbor vote on accuracy
  • TF-IDF 92.2% injury > our 90.9% — say honestly

Step details

Step 0 · Input

NTSB factual narrative · ≥100 chars · first 4,000 chars (none longer in data) · truth codes saved for Step 7 only.

Step 1 · Strip cheat phrases · Red

Remove “substantial damage”, “fatal injuries”, “killed”, “hospitalized”, NTSB report boilerplate, URLs — before phrase match or similar-story search.

Step 2 · Phrase match · runs at same time as Step 3

Same clean story from Step 1. Match to Zhang node names: (1) main outcome (2) people (3) multi-word events. Skip negated/hypothetical clauses. Output goes to Step 5 — not through 4a/4b. Alone: 82.4% injury — not main method.

Step 3 · 100 similar past stories · runs at same time as Step 2

Story search list: every 1982–2006 story saved as a vector once.

Why not add test accidents? They are the exam — search pool must be past accidents only.

Embed clean story → find 100 closest 1982–2006 accidents (k = 100).

Step 4a · Event suggestions · same time as 4b

Uses Step 3’s 100 stories only. If 71/100 had “landing phase” → suggest that node with strength ~0.71. Top 3 if common enough vs baseline.

Step 4b · Injury & damage from neighbors · same time as 4a

Count NTSB coded injury/damage on those 100 accidents.

  • Neighbor vote alone: most common level → 90.9% / 77.4%
  • Severity through network: feed counts into injury/damage nodes → P(each level) → same top pick

Step 5 · Update locked network

MethodInputResult
Severity through network ★Step 4b only90.9% / 77.4%
Neighbor vote aloneStep 4b, no networkSame top answer 296/296
Phrase match + suggestionsSteps 2 + 4a82.4% inj
Combined test (failed)2+4a and 4b together38.5% / 41.9%

Step 6 · Read answers

A) Highest P(injury level) and P(damage level). B) Vote cause category on same 100 stories → 84.2%. Phrase match for causes → 57.7% only.

Step 7 · Grade

Compare to NTSB. Agree on top pick: severity-through-network and neighbor vote picked same #1 on all 296.

Worked example

Story: "...substantial damage... engine instruments..."
Step 1: strip "substantial damage" → one clean story
Step 2 & 3 AT SAME TIME on that clean story:
  Step 2: engine instrument node = YES
  Step 3: find 100 similar 1982–2006 accidents
Step 4a & 4b AT SAME TIME on those 100:
  4b: e.g. 41 none, 28 minor, 24 serious, 7 fatal injury codes
Step 5: severity through network (main path uses 4b)
Step 6: pick highest P(injury); cause vote also from Step 3 pool
Step 7: compare to NTSB (never used as input)

Part 3 — Build network & check Zhang · Blue

C1 · Data

Part 121 accidents · events, findings, persons, injury/damage · BTS 184,517,128 flights.

C2 · Nodes & edges — example

NODES:
  [fire]  [loss of engine power]  [landing phase]
  [person: pilot-in-command]  [pilot error finding]
  [personnel injury: fatal|serious|minor|none]
  [aircraft damage: destroyed|substantial|minor|none]

EDGES (influences):
  fire → loss of engine power → personnel injury
  person: pilot-in-command → pilot error → landing phase
  last events in chain → personnel injury & aircraft damage

Node = one label or severity variable. Edge = “this can affect that.”

C3 · Priors

P(event per flight) = count / 184,517,128 · Example: P(fire) = 102 / 184,517,128

C4 · Parents (max 12)

Each node gets ≤12 best predictor events. Cap keeps probability tables stable. Deterministic = same data → same parents. Chosen by co-occurrence + Zhang edge-ratio rules.

C5 · Beta-CDF smoothing

Rare parent combos → raw 0%/100% nonsense. Zhang’s recipe smooths counts with Beta CDF — we follow paper/code, not free tuning.

C6 · Table 7

102 fires → count P(cause | fire) → 85 rows must match Zhang 85/85.
