# Worked Examples — Live Demo

End-to-end worked examples for the paper's Section 7 (A0) and Section 8.5.1 (A2),
served by a Streamlit app.

## What's here

| File | Purpose |
|---|---|
| `precompute_a0.py` | Runs the A0 (embedding-only) pipeline in **production mode** (full ~2,243 corpus) on a synthetic narrative query. Calls only `main_app` production functions — no parallel math. Saves `data/a0.json` and a human-readable `data/trace_synthetic_a0.txt`. |
| `precompute_a2.py` | Runs the A2 (embedding + structural reranking, α=2.0) pipeline in **held-out mode** (177 train index) on real test incident `20100114X11754`. Currently blocked by iCloud-evicted `embeddings_train.npy`; see note below. |
| `precompute_a2_from_trace.py` | Fallback: parses the validated May-20 trace at `Testing_Structural_Mapping_Slides/outputs/trace_20100114X11754_a2_full.txt` into `data/a2.json`. The trace was produced by the same production pipeline; this script does no math. |
| `enrich_snippets.py` | Adds narrative snippets to retrieval rows in both JSONs by reading `refined_dataset.json`. |
| `generate_html.py` | Renders both JSONs into `worked_examples.html` (self-contained explainer for non-experts). |
| `app.py` | Streamlit demo. Renders the two JSONs as scrollable, step-by-step walkthroughs. |
| `data/a0.json` | Precomputed A0 outputs (generated by `precompute_a0.py`). |
| `data/a2.json` | Precomputed A2 outputs. |
| `data/trace_synthetic_a0.txt` | Full stdout of the A0 production run — paper artifact. |

## How to run

```bash
# From the repo root. Use the venv python; the streamlit shebang is broken
# because .venv was created when the project lived at a slightly different path.

# 1) (Already done) Generate cached results. Re-run only if the query changes.
.venv/bin/python -u Worked_Examples/precompute_a0.py
.venv/bin/python -u Worked_Examples/precompute_a2_from_trace.py   # see note below
.venv/bin/python -u Worked_Examples/enrich_snippets.py            # adds narrative snippets

# 2) Launch the demo.
.venv/bin/python -m streamlit run Worked_Examples/app.py
```

After launch, open the URL printed by Streamlit (default `http://localhost:8501`).

The Streamlit app loads the cached JSONs, so the meeting demo is deterministic and fast (no live API calls during the demo).

## Note on `precompute_a2_from_trace.py`

The clean way to regenerate `data/a2.json` is `precompute_a2.py`, which loads the
177-train embedding index and re-runs the full A2 pipeline. However, on the
current machine `data/processed/embeddings_train.npy` has been evicted by macOS
iCloud (Optimize Mac Storage); `stat` reports `0 blocks` while logical size is
36 MB, and `np.load` fails with *No data left in file*.

To unblock the demo we parse the existing trace at
`Testing_Structural_Mapping_Slides/outputs/trace_20100114X11754_a2_full.txt`
(May 20 run, α=2.0, validated) into the same JSON schema with
`precompute_a2_from_trace.py`. When the train index is restored (right-click →
*Download Now* in Finder, or regenerate it from `merged_dataset_train.json`),
`precompute_a2.py` becomes the authoritative path.

## Why two scripts (instead of one)

`main_app` reads the `NTSB_USE_TRAIN_INDEX` env var at **module import time** to
decide whether to load the full corpus or the train-only index. We need both
modes (Section 7 uses production; Section 8.5.1 uses held-out), so each
precompute lives in its own process.

## Worked-example specs

| Aspect | A0 (Section 7) | A2 (Section 8.5.1) |
|---|---|---|
| Query | Synthetic narrative (~60 words) | Real incident `20100114X11754` |
| Index | Full ~2,243 incidents | 177 train incidents |
| Pipeline | Embedding only | Embedding + structural reranking (α=2.0) |
| Ground truth shown | No | Yes |
| Diagnosis | ✓ | ✓ (A0 and A2 side-by-side) |
| Prognosis | ✓ | — |

## Updating the query

Edit `QUERY` in `precompute_a0.py` or `EV_ID` in `precompute_a2.py`, then rerun
the corresponding precompute script. The Streamlit cache will pick up the new
JSON on next reload.
